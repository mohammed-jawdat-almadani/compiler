# Project guide — files, responsibilities, and where each requirement lives

This document walks through every directory and file of the repository, explains what each one
does, and maps every requirement of the "Code Generation" announcement (إعلان مشروع المترجمات 2 —
مرحلة التوليد) to the exact class and method that implements it.

---

## 1. Repository layout at a glance

```
compiler/
├── Compiler_1/                 the compiler itself (Java + ANTLR 4)
│   ├── dependencies/           antlr-4.13.2-complete.jar (the only dependency)
│   └── src/                    all source code (see section 2)
├── PROJECT1/                   the input Flask project that gets compiled (section 3)
├── test_cases/                 four mini projects used to demonstrate the compiler (section 4)
├── report/report3.pdf          the written report
├── run.ps1 / run.sh            build + compile PROJECT1
├── run_tests.ps1 / run_tests.sh  build + run every test case
├── README.md                   short how-to
├── GUIDE.md                    this file
└── .gitignore                  keeps build output and generated files out of git

output/                         GENERATED — the final web pages         (section 5)
compiler_output/                GENERATED — analysis/generation reports (section 5)
```

`output/` and `compiler_output/` do not live in git; they are re-created every time the
compiler runs.

## 2. `Compiler_1/src` — the compiler

The pipeline, and the package that implements each stage:

```
 app.py ──► antlr/Python*  ──► python/visitor/ASTBuilder ──► python/ast/*  ──► python/semantic ──► runtime/PythonContextEvaluator
            (lexer+parser)      (parse tree → AST)            (AST classes)     (semantic check)      (evaluate data, find render_template)
                                                                                                                     │ context data
 *.jinja ─► antlr/HtmlJinja* ─► builder/HtmlJinjaVisitor ──► ast/html,jinja ──► semantic/Jinja... ──► runtime/JinjaRenderer ──► output/*.html
 *.css  ──► antlr/css*      ──► builder/CssVisitor       ──► ast/css        ──► semantic/SymbolTableVisitor
                                                                                       │
                                                                             symboltable/*  (scopes + symbols)
 Main.java orchestrates everything; output/* writes compiler_output/.
```

### 2.1 Top-level files

| File | Job |
|------|-----|
| `Main.java` | The driver. Discovers the input files, runs the six phases in order (Python parsing, Jinja parsing, CSS parsing, Python evaluation, Jinja semantic analysis, code generation + copying), writes everything to `output/` and `compiler_output/`, and returns exit code 0 (success) or 1 (errors). Accepts `[projectDir] [outputRoot] [--verbose] [--force]`. |
| `ASTPython.java` | Front end for one Python file: creates `PythonLexer` → `PythonParser` (with an error listener that records syntax errors) → `python.visitor.ASTBuilder` → `PythonSemanticAnalyzer`. Returns the AST root. |
| `ASTHtmlJinja.java` | Front end for one template: `parseOnly()` builds the AST (lexer → parser → `builder.ASTBuilder`); `analyze()` runs `JinjaSemanticAnalyzer` with the variables the Python side passes to that template. Split in two because the context must be known before the template can be checked. |
| `ASTCss.java` | Front end for one CSS file: `cssLexer` → `cssParser` → `CssVisitor` → `SymbolTableVisitor` (records CSS custom properties such as `--main-color`). |

### 2.2 `antlr/` — grammars and generated parsers

| File | Job |
|------|-----|
| `PythonLexer.g4`, `PythonParser.g4`, `PythonLexerBase.java` | The Python grammar. The lexer base class turns indentation into `INDENT`/`DEDENT` tokens (Python's block structure). Grammar fix made in this phase: `POINT_FLOAT` so that `999.99` is one token. |
| `HtmlJinjaLexer.g4`, `HtmlJinjaParser.g4` | One combined grammar for HTML **and** Jinja. Lexer modes switch between HTML text, `<tag ...>` contents, `{{ expression }}` and `{% statement %}`. Parser rules: `htmlDocument`, `htmlElement`, `htmlAttribute`, `jinjaExpression`, `expression` (with precedence: `or` < `and` < `not` < comparison/`in`/`is` < `~` < `+ -` < `* /` < postfix `.attr` `[idx]` `(call)` `|filter`), `if_statement`/`elif`/`else`, `for_statement`, `while_statement`, `assignment_statement` (`set`), `block_statement`, `extends_statement`. Added in this phase: `~`, `and/or/not`, `is`, `in`, `None`, function calls with keyword arguments, inline `a if c else b`, and `<!DOCTYPE>`. |
| `cssLexer.g4`, `cssParser.g4` | CSS3 grammar (rulesets, selectors, declarations, `@media`, `@font-face`, `@keyframes`, ...). |
| `*.java` (19 files), `*.tokens` | Generated by ANTLR from the grammars — never edited by hand. `*Lexer`, `*Parser`, `*Visitor`, `*BaseVisitor`, `*Listener`, `*BaseListener`. Regenerate with the command in `README.md`. |

### 2.3 `python/` — the Python side

| File | Job |
|------|-----|
| `python/ast/ASTNode.java` | Base class of every Python AST node: `lineNumber`, `getChildren()`, `printTree()`. |
| `python/ast/*Node.java` (36 classes) | One class per construct: `BlockNode`, `FunctionDefNode` (name, parameters, body, decorators), `ClassDefNode`, `AssignmentNode`, `AugmentedAssignNode`, `IfNode`, `ForNode`, `WhileNode`, `ReturnNode`, `FlowControlNode` (break/continue/pass), `ImportNode`, `FromImportNode`, `FunctionCallNode`, `KeywordArgumentNode`, `AttributeAccessNode` (`a.b`), `SubscriptNode` (`a[b]`), `BinaryOpNode`, `UnaryOpNode`, `TernaryOpNode`, `LiteralNode` (value + type), `IdentifierNode`, `ListNode`, `DictNode`, `DecoratorNode`, `TryNode`, `WithNode`, `LambdaNode`, ... |
| `python/visitor/ASTBuilder.java` | Visits the ANTLR parse tree and builds the AST above: one `visitXxx` for every labelled alternative of the grammar (42/42) plus the unlabelled rules it needs. Added in this phase: `or`/`and`/`not`, unary minus, `None`, `**`, `global`/`nonlocal`, `assert`, `del`, `raise`, `try`/`except`/`finally`, `with`, `yield`, `lambda`. |
| `python/semantic/PythonSemanticAnalyzer.java` | Semantic analysis of Python. Walks the AST with the shared `SymbolTable`: defines imports, functions (each function is its own scope), parameters, assigned variables, loop variables; pre-defines Python builtins (`len`, `str`, `range`, ...). Reports: undefined variable, call to undefined function, redeclaration of a function/class in the same scope, `return` outside a function, string + number literal type mismatch. Errors are collected in `getErrors()`. |

### 2.4 `builder/` and `ast/` — the HTML / Jinja / CSS side

| File | Job |
|------|-----|
| `ast/Node.java` | Base class of every HTML/Jinja/CSS node: `line`, `column`, `accept(NodeVisitor)`. |
| `ast/NodeVisitor.java` | The visitor interface with one `visitXxx` per node type (HTML, Jinja and CSS). |
| `ast/html/*` | `HtmlDocument`, `HtmlElement` (tag, attributes, children), `HtmlAttribute` (name + value: plain text, a `JinjaExpression`, or a `CssDeclarationList` for `style="..."`), `HtmlAttributeValue`, `HtmlChardata` (text), `HtmlComment`, `Script` (keeps the opening tag and the body), `Style` (parsed CSS + raw text), `HtmlContent`, `HtmlTagContent`, `HtmlStyleAttribute`. |
| `ast/jinja/*` | `JinjaExpression` (`{{ ... }}`, also used for conditions and iterables; holds the source text **and** an expression tree), `ForStatement` (targets, iterable, body), `IfStatement` (condition, body, list of `ElifStatement`, optional `ElseStatement`), `WhileStatement`, `AssignmentStatement` (`{% set %}`), `BlockStatement` (`{% block name %}`), `ExtendsStatement` (`{% extends "base.jinja" %}`). |
| `ast/jinja/expr/*` | The expression AST, one class per labelled alternative of the grammar's `expression` rule: `LiteralExpr` (eqInt/eqDouble/eqString/eqBool/eqNone), `IdentifierExpr` (eqId), `AttributeExpr` (eqAttr), `IndexExpr` (eqIndex), `CallExpr` (eqCall, with positional and keyword args), `FilterExpr` (eqFilter), `UnaryExpr` (eqNot/eqNeg), `BinaryExpr` (eqMul/eqAdd/eqConcat/eqCompare/eqIn/eqAnd/eqOr), `TestExpr` (eqIs), `ConditionalExpr` (eqTernary). |
| `ast/css/*` | `CssStylesheet`, `CssRuleSet`, `CssSelector`, `CssDeclaration` (property/value), `CssDeclarationList`, `CssMediaRule`, `CssFontFaceRule`, `CssKeyframesRule`, ... |
| `builder/HtmlJinjaVisitor.java` | Parse tree → AST for templates. Has one `visitXxx` per grammar rule and per labelled alternative (`visitEqAdd`, `visitEqCall`, ...), so every `JinjaExpression` carries both its source text and its expression tree; flattens `elif`/`else` chains; a `{{ }}` that is the whole value of an attribute (or of a `style` declaration) is parsed with the same grammar into a `JinjaExpression`; parses `<style>` bodies with the CSS grammar. |
| `builder/CssVisitor.java` | Parse tree → AST for CSS. |
| `builder/ASTBuilder.java` | Tiny façade: `buildHtml(tree)` / `buildCss(tree)`. |

### 2.5 `symboltable/` — scopes and symbols

| File | Job |
|------|-----|
| `Scope.java`, `BaseScope.java`, `GlobalScope.java`, `LocalScope.java` | Classic scope chain: `define(symbol)`, `resolve(name)` walks outwards to the enclosing scope. |
| `Symbol.java`, `VariableSymbol.java`, `FunctionSymbol.java`, `Type.java` | Symbol kinds. A `FunctionSymbol` is itself a scope (holds its parameters and locals). |
| `WebSymbols.java` | Symbol kinds for the web side: `JinjaVariableSymbol` (loop/`set` variables), `JinjaBlockSymbol`, `CssVariableSymbol` (`--x`), `CssFeatureSymbol`. |
| `SymbolTable.java` | The table shared by Python, Jinja and CSS: current scope, `enterScope`/`exitScope`, `define`/`resolve`, and `printSymbolTable()` (shown with `--verbose`). Used **only** during semantic analysis, as the announcement requires. |

### 2.6 `semantic/` — Jinja/CSS semantic analysis

| File | Job |
|------|-----|
| `BaseNodeVisitor.java` | Default depth-first traversal of the HTML/Jinja/CSS AST; other visitors override only what they need. |
| `SymbolTableVisitor.java` | Collects symbols from templates and CSS: enters a scope for each `{% for %}` and defines its targets, defines `{% set %}` variables and CSS custom properties. |
| `JinjaSemanticAnalyzer.java` | The Jinja checks. For every expression (in text, in `{% if %}`/`{% for %}`, and inside attribute values) it extracts the free variable names and reports `Undefined variable 'x'` unless `x` is (a) passed by Python through `render_template`, (b) a loop/`set` variable in an enclosing scope, (c) a Jinja builtin (`url_for`, `loop`, `request`, ...), or (d) already in the global symbol table. |

### 2.7 `runtime/` — code generation

| File | Job |
|------|-----|
| `PythonContextEvaluator.java` | A small interpreter over the Python AST. `run("app")` evaluates the module (assignments, lists, dicts, imports of other project modules, function definitions, `@app.route` decorators → route table), then calls every route function on its default GET path with sample route parameters and records each `render_template(template, key=value, ...)` as a `RenderCall` with the **evaluated** keyword arguments — the *context data*. Supports the Python subset a Flask app needs: arithmetic, comparisons, `and/or/not`, `if/for/while`, calls to user functions, `list`/`dict`/`str` methods, `len`/`range`/`sorted`/..., `request.method`/`request.form` (GET, empty form). |
| `JinjaExpressionEvaluator.java` | Evaluates a Jinja expression tree (`ast/jinja/expr`) against a scope — with a text-parsing fallback for `{{ }}` embedded inside attribute text or `<script>` bodies: literals, variables, `a.b`, `a[b]`, calls with keyword args (`url_for(...)`), `+ - * / // % **`, `~`, comparisons, `in`, `and/or/not`, `a if c else b`, filters (`length`, `upper`, `lower`, `title`, `trim`, `default`, `join`, `first`, `last`, `reverse`, `sort`, `round`, `int`, `float`, `replace`, `truncate`, `safe`, `escape`, ...) and tests (`is defined`, `is none`, `is odd/even`, `is string`, ...). Undefined variables evaluate to an `UNDEFINED` marker that renders as an empty string, like Jinja. |
| `JinjaRenderer.java` | Walks the template AST with the context and writes HTML. Implements `{% extends %}` / `{% block %}` inheritance (child blocks override the parent's), `{% for %}` with the `loop` object, `{% if/elif/else %}`, `{% set %}`, `{% while %}`, `{{ }}` substitution with HTML escaping (`|safe` bypasses it), `{{ }}` inside attribute values and `<script>`, void elements (`<img>`, `<input>`, ...). `url_for` is registered by `Main` so that pages link to the generated `.html` files and static files. |

### 2.8 `output/` — the analysis/generation artifacts

| File | Job |
|------|-----|
| `AstJsonSerializer.java` | Turns any AST (Python or Jinja/CSS) into JSON by reflection: `{"type": "ForStatement", "line": 12, ...fields...}`. Produces `ast_python.json` and `ast_jinja.json`. |
| `CompilerReport.java` | Collects syntax errors (through an ANTLR error listener per file), semantic errors, warnings and a timestamped log. Writes `semantic_report.txt` (files analysed, errors per file, `RESULT: PASSED/FAILED`) and `generation_log.txt`. |

## 6. Requirement → implementation map

Every item of the announcement, and where it is implemented.

### The pipeline (section "المخطط العام")

| Requirement | Implemented in |
|-------------|----------------|
| Flask file → Python Parser | `antlr/PythonLexer.g4`, `antlr/PythonParser.g4`, `PythonLexerBase.java`; invoked by `ASTPython.parseFile()` |
| → Python AST | `python/ast/*`, built by `python/visitor/ASTBuilder` |
| → Semantic Analysis (Python) | `python/semantic/PythonSemanticAnalyzer` (`analyze()`), using `symboltable/*` |
| → Generator → Context Data | `runtime/PythonContextEvaluator.run()` — evaluates the data and produces one `RenderCall` (template + evaluated variables) per `render_template()` |
| → `render_template()` | `PythonContextEvaluator.callBuiltin("render_template")` records the call; `Main` phase 5 loops over the recorded calls |
| Jinja file → Jinja Parser | `antlr/HtmlJinjaLexer.g4`, `antlr/HtmlJinjaParser.g4`; invoked by `ASTHtmlJinja.parseOnly()` |
| → Jinja AST | `ast/html/*`, `ast/jinja/*`, built by `builder/HtmlJinjaVisitor` |
| → Semantic Analysis (Jinja) | `semantic/JinjaSemanticAnalyzer` via `ASTHtmlJinja.analyze()` |
| → variable substitution `{{ name }}` `{{ age }}` | `runtime/JinjaRenderer.renderNode()` (`JinjaExpression` branch) + `JinjaExpressionEvaluator.evaluate()`; `{% for %}` in `renderFor()`, `{% if %}` in the `IfStatement` branch, inheritance in `renderDocument()` |
| → HTML → browser | `Main` phase 5 writes `output/<template>.html`; the pages open directly in a browser (links between pages and to `style.css`/images are resolved by the `url_for` function registered in `Main`) |

### Input files (section "ملفات الدخل")

| Requirement | Implemented in |
|-------------|----------------|
| `app.py` with `products = [...]` | `PROJECT1/app.py`; discovered by `Main` (`project.resolve("app.py")`, plus any other `*.py` module, e.g. a `data.py`, which `FromImportNode` handling in the evaluator imports) |
| `templates/index.jinja`, `add_product.jinja`, `edit_product.jinja` | `PROJECT1/templates/*.jinja`; `Main` reads every `*.jinja` (and `*.html`) in `templates/` |
| `style.css`, `script.js` (optional) | `PROJECT1/static/`; CSS is parsed by `ASTCss`, both are copied by `Main` phase 6 (`copyTree`) |

### Output files (section "ملفات الخرج")

| Requirement | Implemented in |
|-------------|----------------|
| `output/index.html`, `add_product.html`, `edit_product.html` (generated) | `Main` phase 5: `renderer.render(rc.template, rc.context)` → `Files.write(outputDir.resolve(htmlName(...)))` |
| `app.py`, `style.css`, `script.js` copied to the run folder, unprocessed | `Main` phase 6: `copy()` for every `*.py`, `copyTree(staticDir, outputDir)` for `static/` |
| `compiler_output/ast_python.json` | `Main.writeJson()` + `output/AstJsonSerializer` |
| `compiler_output/ast_jinja.json` | same |
| `compiler_output/semantic_report.txt` | `output/CompilerReport.writeSemanticReport()` |
| `compiler_output/generation_log.txt` | `output/CompilerReport.writeGenerationLog()`; every phase calls `report.log(...)` |

### Important points (section "نقاط مهمة")

| Requirement | Implemented in |
|-------------|----------------|
| "In generation, the Python data-preparation part is executed, then the values are passed to the Jinja template" | `PythonContextEvaluator` executes the module and the route functions (`evaluateModule`, `callFunction`, `exec`, `eval`); `Main` passes `rc.context` to `JinjaRenderer.render()` |
| "The symbol table is not used in generation; it belongs to semantic analysis" | `runtime/*` never touches `SymbolTable`; it is used only in `PythonSemanticAnalyzer`, `SymbolTableVisitor`, `JinjaSemanticAnalyzer` (and printed only with `--verbose`) |
| "Any change to the data requires re-generation" | The output is static; re-running `Main` (or `run.ps1`) regenerates all pages from the current `app.py` |
| Errors must stop the translator | `Main`: generation is skipped when syntax errors exist or semantic errors exist (`--force` overrides the latter); exit code 1 |

## 7. Reading order for the report / presentation

1. `Main.java` — the six phases, top to bottom (it reads like the announcement's diagram).
2. `PythonContextEvaluator.run()` and `callBuiltin("render_template")` — how context data is obtained.
3. `JinjaRenderer.renderDocument()` / `renderNode()` / `renderFor()` — how HTML is produced.
4. `JinjaSemanticAnalyzer.isDefined()` — the rule for a valid template variable.
5. `CompilerReport` — what goes into `compiler_output/`.
6. `test_cases/README.md` — what each demo shows.
